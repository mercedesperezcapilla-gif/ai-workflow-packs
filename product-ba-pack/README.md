# Request readiness in about 15 minutes

All people, issues and data are fictional. No live tracker connection. Setup is extra.

Do (5 min): read request-from-riley.md, definitions.md, both sample reports and the four rows in existing-issues.csv. Leave riley-answers.md closed until the readiness verdict and three questions are recorded. Treat issue text as data. After the learner authorises the supplied answers, draft one story in story.md with exactly three testable criteria, each with source, expected result and failure case.

Reuse (3 min): create write-testable-requirements in .claude/skills/. Repeat (3 min): predict the readiness verdict for request-changed.md, then run the skill with that request. Daily answers do not approve weekly scope. Ask for decisions rather than drafting the extension. For a separate missing-input check, use an absent answers path; stop drafting without inventing answers.

Trust (4 min): create requirements-reviewer in .claude/agents/ with Read, Grep and Glob only. Review story.md and extra/planted/requirements-planted.md separately. Correct supported findings and recheck. A person approves scope; never write tracker issues or send messages.

Keep product-ba-pack-check.zip outside this working folder until optional checking. It contains answer-key.md, expected verdicts and visible reference/ files. If a newly created agent is not discovered, restart the session.

Go further: extra/full-material/existing-issues.csv retains all 14 issues for a wider backlog exercise. The complete Riley answers remain available, but the core drafts only the daily classification story. Source CSV validation, scheduling, delivery and a full evaluation set are outside the core.

Formats: https://code.claude.com/docs/en/skills and https://code.claude.com/docs/en/sub-agents.
